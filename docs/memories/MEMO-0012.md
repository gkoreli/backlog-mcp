In `DocsNativeFilesystemStorage.write()`, the `exclusive && snapshot().byId.has(id)` check (ADR 0129 R9) is load-bearing. Before slugs, the `wx` open flag alone caught two writers minting the same id because both hit the same path. With title-derived slugs, two writers with different titles land on two different paths and `wx` sees no conflict — the atomic-create test went green for the wrong reason during Phase A. In-process the id check is exact; cross-process with a stale memoized snapshot (ADR 0127) the second file can land and the next read quarantines both as a duplicate-substrate-document collision that blocks the type — visible and fail-closed, never a silent overwrite. Related pre-existing wart: the CLI surfaces that SubstrateWriteError as an uncaught stack trace, not a one-liner.
