# 0106.6. One substrate operation path

Engineering status: declared CLI dispatch and threaded creation now use this path
(ADR 0129.2 / 0113.2). Generic update and coordinated memory migration remain pending.

## Context and evidence

Goga identified an incomplete dependency direction: the intent executor calls
generic update while remember owns another pipeline. He directed that updating
and remembering become composable/declarative implementations of substrate
operations and confirmed shared CLI/MCP action semantics as a substrate tenet.

At the start of this change, `core/substrates/execute-substrate-intent.ts` checks
workflow preconditions before calling `core/update.ts`. CLI generic update calls
the latter directly, so its valid postimage need not describe an allowed action.
`core/remember.ts` separately owns validation, memory composition, journaling and
advisory review. `tools/register-substrate-intents.ts` exposes compiled actions,
whereas CLI has generic create/update. Thin adapters alone do not establish one
domain operation authority. The [semantic coherence brief](../proposals/backlog-semantic-coherence-2026-10.md)
records the broader audit.

## Rulings

### R1. One operation contract is a substrate tenet

A substrate declares its supported actions, input contracts and lifecycle rules.
The compiled catalog is the source for CLI and MCP. The same declared action has
the same preconditions, semantic outcomes and domain failures through either
adapter. Transport selection, syntax, formatting and path permissions stay with
their adapters. The engine remains open to project-defined substrates.

### R2. One core executor, composed domain implementations

`executeSubstrateIntent` is the managed action entry point. It validates inputs
against the compiled contract and dispatches supported typed mechanics. Cohesive
core handlers own pure policy, application sequencing and calls to injected
publication capabilities. They do not re-enter public create/update/remember
pipelines. Declarations are data, never executable project-authored code.

Memory capture, retraction, body edits and deletion participate in declared
mechanics as well as create/transition/relation actions. A useful domain verb can
remain ergonomic without owning a second semantic implementation.

### R3. No parallel generic CLI write dialect

Replace generic CLI create/update with catalog discovery and invocation of the
same actions MCP exposes. Existing memory spellings may remain ergonomic bindings
to the declared memory operations. Any retained edit/delete spelling resolves an
operation permitted by the subject's substrate, rather than granting arbitrary
field or lifecycle authority. Unsupported actions fail with discovery guidance.

This supersedes ADR 0106.5's retained generic CLI create/update maintenance tail.
Native human Markdown editing stays available and lossless. No hidden normal
managed-write override may bypass the declared action rules.

### R4. Preserve actual mutation and correction guarantees

Remember retains source provenance, temporal/derived-source validation, explicit
new holders and coordinated predecessor closure for supersedes/state_key. Its
existing home-local lock, exact revisions and recovery diagnostics remain; a
memory correction is not lowered into an ordinary single-file create.

Each action owns its semantic journal attempt and committed receipt. Derived
capture/review failures preserve successful primary writes and their diagnostics.
Read-side recall/search remain distinct contracts. No LLM enters server writes,
no new source of truth or general transaction engine is introduced, and no D1
parity is required.

## Engineering plan

1. Declare supported memory and document mutation mechanics, compile safe inputs,
   and expose those through the existing catalog. Keep unsupported primitives
   honestly quarantined.
2. Extract internal operation implementations and make the executor validate and
   dispatch them. Remove the reverse dependency on public write entry points.
3. Bind CLI catalog discovery/execution and existing MCP tools to those same
   declarations. Retire generic CLI create/update registration and document the
   migration. Preserve specialized receipts and selected-home provenance.
4. Add unit regressions for direct core inputs, declaration ownership, CLI/MCP
   parity, workflow rejection and correction/recovery behavior. Enforce internal
   handler boundaries in architecture checks. Run build/typecheck/workspace tests.
5. Manually exercise built CLI/MCP/core operations in disposable homes, including
   malformed inputs, wrong-home selection and unsupported operations. Record
   actual versus injected dependencies and clean fixtures.

Three temporary unit probes called real core functions, actual compiled built-in
declarations and actual EntitySchema/MemorySchema parsers, with mocked repository

reopens it; direct block execution accepts an input that its compiled schema
rejects for missing blocked_reason; and generic memory update accepts derived
knowledge without sources plus supersedes/state_key fields that remember's
validation rejects or would process as correction. The probes do not claim
filesystem, lock, correction recovery, MCP protocol or real CLI-process coverage.
The probe and four existing focused suites passed: 76 tests across 5 files.
These observations describe gaps, not contracts to preserve in regression tests.

The current four focused suites were rerun after the exploration: 73 tests
passed across 4 files (`execute-substrate-intent`, `builtin-substrate-intents`,
`core-remember-forget`, `memory-capture`). No production code changes remain in
this audit. These unit checks do not establish CLI/MCP process parity or real
filesystem correction recovery. Migration implementation and verification will
be recorded below. No version bump or publication is authorized by this ADR.

### Migration constraints found in the code

1. **Keep the catalog, invert the application dependency.**
   `ProjectSubstrateRegistry.listIntents:93` already combines built-in and
   project actions. The executor currently imports public create/update handlers
   (`execute-substrate-intent.ts:13,22`). Extract their publication mechanics
   below the executor; making public update call the executor while leaving the
   reverse dependency would introduce recursion rather than one authority.

2. **Action inputs are not a projection of the persisted schema alone.**
   `shared/src/substrates/memory.ts:65` defaults a stored memory's layer to
   episodic, whereas `core/remember.ts:110` defaults an explicit remember to
   semantic. Persisted `valid_until` permits null (`memory.ts:73`), whereas
   remember accepts a date string and validates its interval. The current
   compiler permits intent defaults only for create
   (`compile-substrate-intents.ts:331`). Memory operation compilation must
   preserve the action contract instead of inheriting persistence defaults.
   Paths under `shared/` are relative to `packages/`.

3. **Registration and name ownership must migrate together.**
   `tools/register-tools.ts:143,154` registers remember/forget independently,
   before compiled actions at line 165. Their names are currently reserved in
   `core/substrates/tool-name-reservations.ts`. The registry rejects composed
   intents using reserved names (`project-substrate-registry.ts:391`), including
   trusted built-ins. Adding memory declarations alone would fail at startup or
   double-register tools; change ownership without allowing project declarations
   to capture unrelated reserved names.

4. **Preserve receipts and the meaning of success.**
   Remember journals after durable storage (`remember.ts:140`) and returns
   correction metadata, write warnings and tri-state advisory collision results.
   Forget currently returns a count (`forget.ts:63`), with OR matching and
   already-expired GC in `backlog-memory-store.ts:171,181`; it has no affected-ID
   receipt. Generic delete returns `deleted:false` for absence
   (`core/delete.ts:25`), but MCP formats that as "Deleted"
   (`tools/backlog-delete.ts:36`). Common execution must preserve truthful domain
   outcomes, rather than replacing them with a uniform success string or
   fabricating affected IDs.

5. **Retrieval sharing is separate from mutation authority.**
   Search directly calls `searchUnified` (`core/search.ts:15`). Recall calls the
   composer (`core/recall.ts:48`); its default local store also uses
   `searchUnified`, then filters memory layers, exact parent context, tags and
   validity, and applies usage ranking (`backlog-memory-store.ts:129–154`). Core
   recall adds provenance and token-budget packing. These are distinct semantic
   contracts sharing candidate retrieval; this ADR does not merge them.

The first engineering slice should make compiled input validation authoritative
at the executor and add regressions for invalid direct core calls. The following
slice should move publication handlers beneath it, introduce memory operation
contracts with their existing defaults, and migrate catalog/name ownership and
both adapters together. An adapter-only rewrite would leave the observed core
bypasses intact.
