# ADR corpus conformance

## Context

Promoting ADRs to a compiled substrate exposed historical corpus debt: of 174
numbered Markdown files, 102 lacked frontmatter. Other records mixed lifecycle
states with implementation notes, used undeclared metadata, or shared identities.
A duplicate claim correctly blocked managed ADR creation (TASK-0014).

The maintainer directed that ADR documents conform first; a reusable corpus
checker and the Bun runtime migration remain subsequent work.

## Decision

### R1. Canonical metadata, preserved decisions

Every decision has a filename-matching engine identity, `type: adr`, a semantic
title, a canonical lifecycle value and an authored short discovery description.
Metadata is validated by the selected home's compiled ADR schema. Preserve actual
historical dates rather than inventing creation timestamps. Preserve former
status wording, authorship and noncanonical annotations as labelled provenance
in `evidence`; contextual links use `references`.

Implementation progress is distinct from decision acceptance. Preserve explicit
ratification; keep uncertain or unratified work proposed. Scoped overrides stay
explicit in the body and provenance, without implying whole-document replacement.
Active typed relations name existing targets in the selected home; references to
historic external/global work remain provenance rather than fabricated entities.

### R2. One identity per decision

Unrelated duplicate decisions receive fresh root identities from the existing
core allocator, with their original headings, dates and former IDs preserved.
This is a bounded, explicitly authorized native corpus migration. It changes no
allocation guard or managed action contract.

The original knowledge-graph decision keeps ADR 0008; static-file serving keeps
ADR 0018. Audits and execution briefs remain generic supporting resources with
valid frontmatter, not additional decision entities. The index links them beside
their decision threads. Historical evaluation outputs keep their captured
addresses; they are historical measurements, not current navigation contracts.

### R3. Validate with actual readers and write semantics

Bun 1.4.2 native YAML parses the normalized frontmatter independently. The current
backlog reader and selected-home registry validate the same records, including
filename identity, lifecycle, description, relation targets and canonical
frontmatter serialization. The latter matters: schema-valid YAML alone need not
pass the current managed-adoption guard. This pass uses the existing canonical
writer's formatting while preserving decision bodies apart from necessary link
relocations. No parser, schema or publication guard is weakened.

## Consequences

The ADR corpus becomes discoverable through descriptions and usable through
native entity contracts without another adoption step. Historical headings in
reallocated records intentionally retain their former numbers; frontmatter and
filenames are authoritative, and provenance explains the reconciliation.

Supporting documents remain readable and collocated by thread in `adr-support/`.
A future checker must distinguish declared entities from generic supporting
resources. This decision does not impose ADR metadata on every Markdown resource.

## Engineering record

One-off corpus validation uses real repository reads, Bun's native YAML parser,
the installed Markdown reader and the selected-home registry/storage projection.
It checks all decision files; this is manual corpus validation, not a unit test
that writes to the real filesystem. Original decision bodies are compared with
the pre-normalization snapshot, allowing only recorded relocation changes.

The runtime, package manager, lockfile and test framework remain unchanged in
this pass. The checker and Bun migration require their own engineering work.

### Validation

All 171 ADRs (170 migrated decisions plus this engine-created thread record)
pass Bun 1.4.2 YAML parsing, the current reader, the compiled schema, filename/ID
agreement, unique identity, description and declared relation checks. Their
frontmatter equals the current writer's canonical serialization. Of 174 original
documents, 171 bodies are byte-identical; three have only necessary relocation
or navigation edits. The four supporting documents have valid resource YAML.

Build, typecheck and all 1,875 workspace unit tests pass. The built CLI allocated
this record as ADR 0113.3 and accepted it through declared actions after the
duplicate claims were reconciled. No schema or runtime code changed. Bun's
[native YAML API](https://bun.com/docs/runtime/yaml) is used for the independent
audit. Migration to Bun 1.4.2 ([release notes](https://bun.sh/blog/bun-v1.4.2))
remains deferred.
