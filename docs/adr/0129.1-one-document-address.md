# 0129.1 — One Document Address

## Context — "Resource not found" on a task that exists

On `http://localhost:3030/?home=project&project_root=…/blog&id=MEMO-0091`,
clicking the memory's referenced task produced:

```
TASK-0092.md
mcp://backlog/tasks/TASK-0092.md
Failed to load resource — Resource not found
```

The file exists at `blog/docs/tasks/TASK-0092.md`. ADR 0129 R8 had recorded
this gap as "Phase B"; it is wider than described there. Every entity link in
a project home fails, slug or no slug.

## Audit — three dialects for one question

"Which document is this?" was answered three different ways:

| Surface | How it resolved | File |
|---|---|---|
| `backlog_get` / CLI `get` | inline helpers: `isResourceUri`, `pathAliasUri`; entity ids via `getMarkdown`, paths aliased to `mcp://backlog/<path>` | `core/get.ts:12-27, 71-90` |
| HTTP `/mcp/resource` | accepts only `mcp://backlog/…`, maps it to `<home.root>/<path>` through `ResourceManager.resolve` | `server/hono-app.ts:893-935`, `resources/manager.ts:236-266` |
| Viewer | **synthesizes** `mcp://backlog/tasks/${id}.md` from an id | `components/task-detail.ts:154`, `metadata-card.ts:84,149`, `collision-candidates.ts:30` |

The viewer's dialect is a relic of the `.backlog-mcp` layout, where the
resource root *was* the data directory and every entity sat flat under
`tasks/`. ADR 0112 moved truth into `docs/` with per-substrate folders,
sub-folders allowed, and human filenames; ADR 0129 added slugs. The resource
manager is rooted at `home.root` with `docs/` as the addressable surface, so
`tasks/TASK-0092.md` resolves to `blog/tasks/…`, outside `docs/`, and is
refused as "outside the documents surface". Only the global home could have
hidden this, and nothing there opens through the pane.

Storage already knows where every entity lives: `getFilePath(id)` returns the
absolute path of the claimed document (`docs-native-filesystem-storage.ts`),
and `ResourceManager.toUri(path)` maps an absolute path back to its URI. The
two capabilities were never composed.

## Rulings

**R1 — One address grammar, in core.** `core/document-address.ts` owns
`DocumentAddress`: an entity id, a root-relative path (aliased to its URI), or
an `mcp://backlog/` URI. `parseDocumentAddress` classifies; `resolveDocumentUri`
turns an address into the URI that reads it. Threaded ids such as `ADR 0113.1`
stay entities: only a slash or an *alphabetic* extension marks a path.

**R2 — Entities resolve through the service, never through a synthesized
path.** `IBacklogService.getResourceUri?(id)` composes storage's
`getFilePath` with the resource manager's `toUri`. That follows the document
into any folder or filename the home uses. D1 does not implement it; there the
address resolves to `null` and the caller fails closed (ADR 0104 posture).

**R3 — Every adapter calls core.** `core/get.ts` drops its private helpers for
`parseDocumentAddress` (same behavior, one owner). The HTTP proxy accepts
`address` (with `uri` as an alias for existing links), resolves through R1/R2,
and only then reads. The viewer passes the bare id as the pane address; a
resource URI still works unchanged. `isDocumentAddress` in
`viewer/utils/document-address.ts` is the viewer's only knowledge of the
grammar, used to recognize a persisted pane and an internal link.

**R4 — Unknown ids fail closed with a named reason.** `No document for
TASK-9999 in this home`, never a path error, never a silent null.

**R5 — Resource-manager path resolution is unchanged.** The catch-all
`mcp://backlog/{+path} → {root}/{path}` mapping (ADR 0006/0007) and its
containment checks remain the one place a URI becomes a file. This ADR adds
the id → URI hop in front of it; it does not add a second file resolver.

## Engineering

- `core/document-address.ts` (new) + `__tests__/document-address.test.ts`.
- `storage/backlog-service.contract.ts`: `getResourceUri?`; implemented in
  `storage/local/backlog-service.ts`.
- `core/get.ts`: uses `parseDocumentAddress`.
- `server/hono-app.ts` `/mcp/resource`: `address ?? uri` → resolve → read.
  Route test `__tests__/hono-document-address.test.ts`.
- Viewer: `utils/document-address.ts` (+ test); `task-detail.ts`,
  `metadata-card.ts`, `collision-candidates.ts` address by id;
  `split-pane-state.ts` restores any document address; `resource-viewer.ts`
  sends `address`. Tests updated to assert ids, not synthesized paths.

## Validation

- Unit suites green.
- Live: the blog home's MEMO-0091 → TASK-0092 link opens the task; the pane
  header shows the resolved `mcp://backlog/docs/tasks/TASK-0092.md`; an
  unknown id returns the R4 message; the `uri` alias still serves an existing
  `mcp://backlog/docs/…` link.
