# Engine-owned thread allocation

## Context

A decision family could occupy one huge ADR. Splitting it into focused `x.n`
documents keeps related decisions adjacent while letting humans and agents read
only the relevant amendments. Semantic filename slugs signal the subject before
opening a document. Grouping alone does not replace or overrule earlier rulings.

The core already recognizes dotted identities, but `nextStorageDocumentId`
allocates roots only. Native Markdown can have human-authored dotted IDs;
managed creation needs an engine-owned allocation policy, not caller-selected IDs.
`executeSubstrateIntent` also currently trusts adapter input validation.

## Rulings

**R1 — Declare thread allocation on a create action.** A declaration may specify
`allocation: { strategy: "thread-child", threadInput: "thread" }`. The selector
must be an exposed input and the substrate identity must support dotted keys.
It is an action input, not a persisted field or a containment `parent_id`.
Optional omission allocates a root; a supplied `thread` selects an existing
same-substrate document in the selected home. No caller chooses the generated ID.
The native ADR propose action exposes this optional input.

**R2 — Core validates and generates; the storage port commits atomically.** Core
checks the compiled input contract and the selected document's type and identity.
It generates the next immediate child using the largest occupied child number
plus one. Storage supplies fresh document claims inside the same home lock used
for the exclusive write. Quarantined claims reserve numbers, duplicate identities
and incomplete scans fail closed, and unavailable atomic capabilities fail closed.
No preview-then-write fallback is allowed for thread allocation.

**R3 — Collocate the child with its selected thread document.** A child is written
in the existing document's actual directory, including a nested directory within
the substrate claim. Title-derived slugs remain decorative and frozen on creation.
The selected document is neither rewritten nor adopted. Selecting a child can
create a deeper branch (`x.n.m`); creation does not imply lifecycle transitions.

**R4 — CLI and MCP consume the same declared action.** CLI catalog discovery and
dispatch expose the selected home's compiled actions and exact input contracts.
Both surfaces execute through `executeSubstrateIntent`. This implements the
thread-creation slice of ADR 0106.6; generic update and memory migration remain
pending under that ADR rather than being declared complete here.

**R5 — State changes in authority explicitly.** A thread is a reading structure,
not automatic supersession. Amendments name the earlier ADR and affected ruling,
what is overruled, and what remains in force. Whole-document `supersedes` retains
its existing meaning. Machine-readable partial-ruling authority is a separate
future design; Markdown can express the scope today. The skill reference explains
selective reading, concise documents, slugs, and scoped supersession.

## Engineering

Shared declarations and compiler resolve allocation into a typed create policy.
Core owns the pure allocation planner and the action input validation. A separate
atomic thread-creation port prevents constrained adapters silently creating roots.
Local storage composes the planner with fresh claims and exclusive insertion;
the service preserves indexing warnings and core preserves one journal attempt.
CLI discovery/dispatch is a thin adapter over the existing catalog and executor.

## Validation

Implemented in the shared create-policy schema/compiler, core allocation planner,
atomic local thread-creation port, and peer CLI/MCP action dispatch. The portable
skill's threads reference records the selective-reading and amendment convention.

- `pnpm build`, `pnpm typecheck`, and `pnpm test` pass. The complete workspace
  has 1,875 passing unit tests (1,656 server, 163 viewer, 56 memory), with two
  pre-existing skipped server tests. Tests use memfs; repository probes only read.
- Manual built CLI: a native root in `adr/architecture/` with quarantined and
  orphan-branch claims generated `ADR 0106.7` beside the root, without changing
  its bytes. Text and JSON discovery preceded explicit get hydration.
- Manual real MCP SDK transport: proposed the next child `ADR 0106.8`, returned
  matching provenance/discovery, and concurrent calls generated distinct `.9`
  and `.10` siblings.
- Invalid descriptions, path-shaped selectors, wrong types, missing threads,
  duplicate identities and cross-home selection failed without document writes.
  A project-defined RFC used the identical declared allocation policy successfully.
- Independent read-only architecture review checked ADR 0134/0136, identified
  six promotion/disclosure issues, and verified their corrections. The ratcheted
  import checks pass without adding exceptions.
- The Markdown reader preserves valid empty bodies. Both a memfs regression
  and the built CLI confirm that an empty-body proposal survives get and accept.
  Disposable manual homes and their recent-home entries were removed afterward.

Remaining ADR 0106.6 work is generic update and coordinated memory operations;
thread creation does not claim that full migration is finished.
