# Native document discovery before hydration

## Context

An agent should choose a document from its name, thread, description, and metadata
before loading its body. Skill discovery demonstrates this ergonomic pattern.
The North Star now makes it a tenet of an agent-native database of documents.

ADRs already ship as `builtin:adr@1` in the packaged declarations. Older entities
use compiled Zod schemas; ADR, requirement, and prompt use data declarations.
`AnyEntity` and `RegisteredSubstrate` retain that implementation split. It must
not define a product-level distinction in native document capabilities.

Today `listItems` returns only identity/title/status/type, `searchItems` returns
match snippets, and the packaged ADR schema has no short description field.
The search disclosure's fields control indexing rather than returned metadata.
Descriptions need an explicit authoring and discovery contract.

## Rulings

**R1 — ADR is a compiled native entity.** The maintainer explicitly selected the
same native entity family as task and memory. Add `EntityType.Adr`, shared
`AdrSchema` and substrate metadata. Shared owns canonical schema/identity; the
server owns ADR workflow, relations, actions and disclosure. Remove the former
packaged ADR declaration so there is exactly one active owner. A project cannot
replace the compiled ADR type; it can define additional document substrates.
This supersedes ADR 0113's ADR-as-packaged-declaration implementation choice,
without closing the custom substrate catalog. Native reads remain lossless.

**R2 — Describe before hydrating.** New default ADR proposals require a concise
authored `description`, targeting roughly 50 tokens. Enforce a deterministic
character ceiling rather than pretending characters exactly measure model tokens.
Existing native and previously managed documents remain readable without a description and are not
rewritten; agents can add authored descriptions incrementally. No server LLM or
automatic body summarization enters the write path.

**R3 — Separate discovery projection from indexing.** Substrate declarations can
select compact frontmatter for list/search discovery independently of searchable
fields. Default ADR discovery includes description, date, and decision lineage;
source paths expose semantic slugs and identity metadata exposes thread context.
Bodies are retrieved through get or an explicit full-content option. A missing
description is visible as missing rather than replaced with an invented summary.
Projection bounds protect against oversized native frontmatter.

**R4 — Thread and authority are distinct.** Preserve ADR 0129.2's engine-owned
child allocation. Descriptions orient; explicit ruling scopes and typed relations
establish decision lineage. Neither a description nor thread numbering replaces
reading the relevant accepted rulings.

**R5 — Preserve retrieval semantics.** Search locates current corpus documents;
recall retrieves learned knowledge with its existing provenance/lineage semantics.
The declaration compiler currently accepts recall projections, but the core recall
implementation delegates only to the memory composer. Substrate-wide recall needs
its own engineering under ADR 0106.6; this change does not disguise search as recall.

## Pattern grounding

ADR [0134](0134-engineering-rules.md) and [0136](0136-domain-ownership-and-application-patterns.md)
are binding. The change uses the [Domain Model](https://martinfowler.com/eaaCatalog/domainModel.html)
for typed policy, [Service Layer](https://martinfowler.com/eaaCatalog/serviceLayer.html)
for use-case orchestration, and [Repository](https://martinfowler.com/eaaCatalog/repository.html)
for persistence isolation. These patterns inform the existing boundaries; they do
not justify another framework or duplicate domain authority.

## Engineering

Add a declaration-driven compact discovery projection and consumer-owned read port.
Core shapes list/search results; local storage supplies real paths and identities.
Default ADR proposals require descriptions, with compatible reads of old files.
CLI and MCP retain their shared core outputs. Document the authoring and selective
reading workflow in the portable usage skill.

## Validation

Implemented as `AdrSchema` / `AdrSubstrate` in shared and one ADR policy module
for workflow, relations, intents and disclosure. Built-in registration compiles
all of those policies into the existing registry; the old packaged ADR owner is
removed. Native ID helpers honor the shared identity declaration.

Core owns bounded frontmatter projection; storage supplies real document identity
and source paths, and CLI/MCP consume the same shaped results. Prior managed ADRs
retain optional timestamp/description compatibility and canonical field ordering.
New proposals require description; native adoption chooses an explicit lifecycle
state rather than inventing one.

Full build, typecheck and 1,875 workspace unit tests pass. Unit regressions cover
pre-promotion and empty-body lifecycle actions, identity helpers, body-free discovery, bounded
metadata, declaration rejection, and ADR exclusion from unfiled work. Manual
CLI/MCP checks confirm description-first discovery and explicit body hydration;
see [ADR 0129.2 validation](0129.2-engine-owned-thread-allocation.md#validation).

Compiled ADR replacement is deliberately rejected with diagnostics. Existing
native files are not migrated or bulk rewritten. Substrate-wide recall and
partial-ruling authority remain the explicit follow-ups in R5 and ADR 0129.2 R5.
