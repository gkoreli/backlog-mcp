# Read-only corpus checking

## Context

Native Markdown remains authoritative and editable. Managed writes validate their postimages, while discovery intentionally projects missing IDs and titles for reading. That projection cannot prove that authored documents conform. The maintainer requested a linter across the docs corpus after ADR normalization.

## Evidence

- `core/document-discovery.ts` supplies a bounded scan and read failures.
- `core/substrates/claim-substrate-documents.ts` owns storage claims and collision detection.
- `core/substrates/project-substrate-registry.ts` owns canonical write validation.
- `storage/local/docs-native-read-model.ts` supplies IDs, types and titles and therefore conceals authored omissions if used as a validator.
- `cli/runner.ts` starts the runtime and records recent homes; diagnostics need a smaller read-only composition.

## Decision

### R1. Inspect authored data

One core checker consumes one discovery snapshot, its compiled registry, registry diagnostics and an injected YAML codec. Parse raw metadata and exact body; do not validate a fabricated read projection. Require frontmatter for claimed entities, canonical ID/type agreement, valid schema values and declared relation targets. Supporting resources remain resources; their YAML must parse when present. Slugs are descriptive, not a title equality invariant.

### R2. Reuse domain owners

Claim matching, identity parsing and canonical schema validation retain their existing owners. The registry retains every declared relation contract independently of which relations are disclosed during get. Validate dangling, wrong-type and self references; derived inverse edges do not require authored inverse fields. Thread adjacency is grouping, not replacement authority. Orphan threads are visible warnings, preserving the allocator's existing reservation policy. No new lifecycle/supersession invariants are invented by the checker.

### R3. Report honestly

Return a deterministic versioned report with document/entity/resource counts and source-path diagnostics. Invalid declarations and unreadable paths prevent a valid result. Missing frozen version history stays a warning under ADR 0122. CLI exits 0 when valid, 1 for corpus violations or incomplete checking, and 2 when invocation cannot run. MCP returns the same report; defects in documents are a successful diagnostic operation.

### R4. Read-only composition

`backlog check` and `backlog_check` call the same core operation. The CLI checker resolves an existing selected home and reads without creating folders, recent-home entries, indexes, operation logs, memories or repairs. MCP receives the selected home's checker capability. Existing selection defaults remain pending TASK-0021.

### R5. Canonical metadata, not YAML typography

Managed adoption compares raw authored metadata structurally with the registry-validated canonical metadata. Quote style and property order cannot require adoption. Missing identity/type, defaults materialized by validation, transformed values and unknown properties still require explicit adoption. This replaces only the previous serialized-YAML typography comparison; it preserves the native-edit/write boundary.

## Engineering plan

Add cohesive core checker contracts, diagnostics and relation retention; wire one filesystem snapshot in composition; add thin CLI/MCP adapters; verify malformed YAML, missing fields, claim collisions, custom undisclosed relations, incomplete scans and read-only behavior with memfs. Run real Bun CLI/MCP checks against the repository and disposable adversarial homes, then record results here.

## Consequences

Projects can diagnose drift before managed mutation without silently repairing human documents. A clean report establishes declared contracts at one observed scan; it does not make all later native edits valid or establish a transactional filesystem snapshot.

## Validation

Implemented on 2026-10-07. The pure checker and relation projection live in
`core/corpus-check.ts`, `core/corpus-check-relations.ts` and
`core/substrates/compile-substrate-relations.ts`. Registry-wide
`CompiledSubstrateRelationEdge` retains undisclosed edges;
`CompiledDisclosureRelation` remains its compatible selective-read alias.
`core/document-canonical-metadata.ts` owns the shared adoption/checking policy.

`composition/corpus-checker.ts` compiles declarations from the same bounded scan
it checks. CLI `check` uses a read-only selection composition. MCP has an injected
selected-home checker resolver: `server/mcp-route.ts` recognizes the diagnostic
call before managed runtime acquisition. `LocalRuntimeRequestResolver.resolveHome`
shares home selection without starting services. A missing selected-home
capability fails closed rather than using the boot home's checker.

Workspace build/typecheck and all unit suites pass under Bun 1.4.2 with Vitest
4.1.10: server 1,679 passing, one existing expected failure and two existing
skips; viewer 163; memory 56. Focused memfs checks cover authored omissions,
normalization, frontmatter content shadowing, collisions, undisclosed custom
relations, incomplete scans, home selection and exact read-only effects.

Actual built Bun processes exercised CLI and the real MCP SDK, including the
HTTP/MCP request path. A clean selected home returned exit 0; document defects
returned exit 1; an invalid CLI selection returned exit 2. Malformed YAML,
invalid schema/declarations, collisions, dangling references and escaping
symlinks failed closed. Cold MCP checking never acquired a managed runtime.
File, directory and control-state snapshots remained unchanged. Native YAML
quote/key-order variations stayed editable through the actual ADR accept action.
Disposable homes were removed.

The complete repository scan observed 370 documents: 270 entity candidates,
100 resources, 94 errors and 23 warnings. All 173 ADR documents had zero
diagnostics. Remaining historical defects are outside the ADR normalization
scope: missing identity/type fields, invalid supporting YAML, duplicate path
keys and references to an absent folder. Numbered unregistered reports remain
visible resources with warnings. This result does not claim the whole repository
corpus is clean or silently reinterpret its old records.

The checker validates declared data contracts, not prose headings, rationale
quality or model quality. Bun's parser accepts duplicate mapping keys with the
last value winning; its API provides no strict-key/AST diagnostic capability.
This checker does not claim duplicate-YAML-key linting.
